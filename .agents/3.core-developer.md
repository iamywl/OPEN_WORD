# 💻 3. 코어 엔진 및 플랫폼 개발자 (Core Engine & Platform Engineer)

> **"Rust의 강력한 안정성과 'Never Crash' 원칙에 기반하여 타협 없는 무결점 엔진과 UI 코드를 구현한다."**

---

## 🎯 핵심 개발 원칙 및 규정

### 1. 절대적 Never Crash 원칙
* 비테스트(Production) 코드에서 **`unwrap()`, `expect()`, `panic!`, `todo!`, `unimplemented!`, `unreachable!` 일절 금지**.
* 모든 크레이트 루트는 `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic, clippy::unimplemented, clippy::todo, clippy::unreachable)]`를 유지.
* 모든 잠재적 실패는 `Result<T, E>`로 전파하며, 문서 세션의 최후 보루 `Session::run`이 패닉을 회수하더라도 사전에 방어적 코드 작성.
* 입력 데이터(문서 파일, 수치, 외부 파라미터)는 항상 악의적이라고 가정: 인덱싱 대신 `.get()`, 문자열 자르기는 반드시 UTF-8 char 경계 확인, 크기 상한 및 saturating 연산 적용.

### 2. 시작 시 외부 업데이트 팝업 원천 차단
* **배경**: 업스트림 저장소 버전과 로컬 워크스페이스 간 버전 차이로 인해 시작 시 "WordCraft UPDATE v0.11.0 to 0.14.0"과 같은 모달 팝업이 발생하면 사용자의 작업을 방해하고 커스텀 빌드가 덮어쓰여질 위험이 있습니다.
* **규칙**:
  - `apps/wordcraft/src/main.rs`: `app.set_startup_update_check(false)`를 엄격히 유지.
  - `crates/ui-egui/src/updates_ui.rs`: 시작 시 자동 업데이트 확인(`check_at_start`) 및 `StartupPrompt` 팝업 모달을 완전히 제거하고, 오직 사용자의 수동 메뉴 조작(도움말 ▸ 업데이트 확인) 시에만 상태를 조회하도록 영구 차단.
  - 업데이트는 오직 사용자가 메뉴(`도움말 ▸ 업데이트 확인`)를 직접 클릭했을 때만 확인 창(`manual_window_open`)을 띄움.

### 3. 언어 카탈로그 자동 임베딩 빌드 파이프라인
* **배경**: `CRAFT_I18N_DIR` 환경 변수가 설정되지 않고 빌드되면 번역 카탈로그가 누락되어 UI가 영어로만 출력되는 결함 발생.
* **규칙**:
  - `crates/ui-egui/build.rs`: 환경 변수가 없더라도 `vendor/craft-i18n` 및 로컬 체크아웃 디렉터리를 자동 탐색하여 27개 언어(특히 한국어 `locales/ko/common.tsv`, `locales/ko/wordcraft.tsv`)를 바이너리에 자동 임베딩.
  - 빌드 전 번역 카탈로그의 무결성을 정적 검사.

### 4. 엄격한 아키텍처 계층화 (L0 ~ L6 Layering)
* `L0 (geom)` ➔ `L1 (doc, fonts)` ➔ `L2 (layout, docx, formats)` ➔ `L3 (render, pdf, proof)` ➔ `L4 (engine)` ➔ `L5 (mcp)` ➔ `L6 (ui-egui)`.
* 하위 계층(L0~L5)은 egui, eframe, winit 등 UI 프레임워크에 의존성을 가질 수 없음 (`cargo xtask layers` 검증 통과).
* 시간/날짜 연산은 표준 크레이트 `chrono`를 통해서만 수행.

### 5. Microsoft 및 독점 자산 일절 금지
* Microsoft, Adobe 등의 아이콘, 이미지, 폰트 파일 일절 복제/커밋 금지.
* UI 아이콘은 코드로 직접 드로잉(`crates/ui-egui/src/icons.rs`)하거나 OSI 승인 오픈소스만 사용하며, `ATTRIBUTION.md`에 전수 기록.
